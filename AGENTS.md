# AGENTS.md

Guidance for AI coding agents working in this repository.

## What this is

A small, dependency-free Bash toolkit that generates a `docker-compose.yml` and a `Dockerfile` for serving a PHP app with FrankenPHP (base image `dunglas/frankenphp:1-php${PHP_VERSION}`, or `dunglas/frankenphp:1` = latest PHP when `PHP_VERSION` is empty). There is no build, lint, or test suite. The files are meant to be copied into a consuming PHP project: consumers download each file from `raw.githubusercontent.com/xaamin/frankenphp-composer/refs/heads/master/...` with the `bash/dockerize` script (kept in this repo; consumers keep a copy in their project). **All scripts live in `bash/` (`bash/compose`, `bash/reload`, `bash/dockerize`) and each starts by `cd`-ing to the project root (the parent of `bash/`, keeping the logical path so Deployer's `release` symlink is preserved), so they work from any directory while every relative path in them (`.env`, `Caddyfile`, templates, `.caddy/`) stays relative to the project root.** **Paths are fetched one by one from the `FILES` list in `bash/dockerize`, so when renaming, moving, adding or removing a distributed file, update that list. Copies already in consumer projects keep the old list, so a removed path makes their `dockerize` fail until they fetch the new one.** Templates use the `.template` suffix, placed before the real extension when there is one (`docker-compose.template.yml`, `Dockerfile.template`); they were previously `*.t`, and `dockerize` warns about leftover `*.t` files. Keep the usage text printed by `dockerize` in sync with `compose` and the README.

## Usage

`bash/compose` works on the root of the consuming project, and the app is served from that project's `public` folder. It takes a container name (`-n`, required) and exactly one of:
- **`-s <domain>` (custom TLS mode):** serves your own certificate files from `.caddy/certs/` and binds ports 80/443.
- **`-s <domain> -a` (auto mode):** Caddy issues the certificate itself: via ACME for public domains, or from its internal local CA for `localhost`/`*.localhost` (the recommended dev setup; its root is at `.caddy/data/caddy/pki/authorities/local/root.crt` and must be trusted on the host because of `skip_install_trust`). No cert is generated into `.caddy/certs/`. `-a` without `-s` is an error.
- **`-p <port>` (port mode, e.g. behind a reverse proxy):** no TLS; binds only the given port.

Optional flags: `-u`/`-g` override the host UID/GID, and `-v` enables verbose output. The PHP version comes from `PHP_VERSION` in `.env`, not a flag; when it is empty `compose` drops the `-php` suffix (`FRANKENPHP_TAG="1${PHP_VERSION:+-php${PHP_VERSION}}"`). After generating the files, the container is started with `docker compose up -d`; the image tag is `${COMPOSE_PROJECT_NAME}-php:df-<cksum of Dockerfile>` (`IMAGE_TAG`), so Compose only builds/recreates when the Dockerfile changes (a plain rebuild yields a new image ID even when fully cached, which would recreate the container).

`-d <deploy_path>` enables **Deployer mode**: `DATA_VOLUME` becomes the deploy path (mounted at the same path), `APP_ROOT` becomes `<deploy_path>/current`, and an override replaces `build` (context `<deploy_path>/shared/.frankenphp`, where the Dockerfile is copied), `volumes` (deploy path + `shared/.caddy/{data,config,certs}`), `working_dir` and `command` (`frankenphp run --config $APP_ROOT/Caddyfile`). Every path must be identical across releases or `docker compose up` recreates the container. **`bash/reload`** reads `container_name` from the target's `docker-compose.yml` and runs `docker exec -e APP_ROOT=<real release path> <name> frankenphp reload --config <release>/Caddyfile --force` (graceful; in local mode `APP_ROOT == DATA_VOLUME` and it just reloads). It must run before `deploy:symlink`: switching `current` alone serves stale code for up to `realpath_cache_ttl` (120 s) or 400s, because `php_server` resolves the root symlink when the config loads. It exits 0 with a warning when the container isn't running (first deploy).

## How the pieces fit

- **`bash/compose`** is the entry point. It parses the flags and exports `NAME`, `DATA_VOLUME`, `HOST_UID`, `HOST_GID`, `SERVER_NAME`, `SERVER_PORT`, `PHP_VERSION` and `COMPOSE_PROJECT_NAME` (shell env, else the last `PHP_VERSION=` line in the project `.env`, else empty; always exported, even when empty, to avoid a Compose "variable is not set" warning). `COMPOSE_PROJECT_NAME` follows the same shell → `.env` order (via the `env_value` helper) and falls back to `-n` lowercased with every run of characters other than `[a-z0-9-]` (including `_`) turned into a single `-`, trimmed at both ends. Then:
  0. **Renders `Dockerfile` from `Dockerfile.template`** with `sed`, replacing `{{FRANKENPHP_TAG}}` on non-comment lines only (a `{{...}}` placeholder rather than `${...}`, so it can't be confused with Dockerfile `ARG`/`ENV` syntax). It fails with 👻 if `Dockerfile.template` is missing. The generated `Dockerfile` is gitignored.
  1. **Edits `Caddyfile` in place** with `sed`. The `tls` line is committed commented out (the safe default for port mode). Port mode and auto mode comment out the `tls` line; custom TLS mode uncomments it and only warns if `.caddy/certs/${NAME}.pem` / `${NAME}-key.pem` are missing (it never generates certificates). `compose` also pre-creates `.caddy/{certs,data,config}` so Docker doesn't create them root-owned on Linux. In-place `sed` editing differs between macOS (BSD) and Linux (GNU), and the script handles both; keep both branches working.
  2. In port mode, sets `SERVER_NAME=":<port>"` so Caddy listens on that port. It also writes a temporary compose override that uses `ports: !override` to replace the default 80/443 bindings.
  3. Renders the final `docker-compose.yml` by merging the template with the optional override via Docker Compose's `config` command. The generated `docker-compose.yml` is gitignored.
- **`Dockerfile.template`** is the image template: `FROM dunglas/frankenphp:{{FRANKENPHP_TAG}}`, then system packages and PHP extensions via `install-php-extensions`. Consumers customize extensions here.
- **`docker-compose.template.yml`** is the compose template. It builds the image from `Dockerfile` (`build: context: .`), uses `${VAR}` interpolation, which is resolved at `config` time, and runs the container as the host UID/GID. It bind-mounts the project at `${DATA_VOLUME}`, plus `.caddy/data`, `.caddy/config`, `Caddyfile` → `/etc/frankenphp/Caddyfile`, and `.caddy/certs` → `/etc/caddy/certs` (read-only). It passes `APP_ROOT` to the container.
- **`Caddyfile`** reads `{$SERVER_NAME}`, `{$APP_ROOT}` (served folder: project dir, or the release in Deployer mode) and `{$NAME}` from the environment when the config is loaded; `reload` overrides `APP_ROOT` per release. The `tls` cert paths are `${NAME}.pem` and `${NAME}-key.pem`; keep them in sync with the check in `compose` and the README.

- **`.env.example`** is also read by `bash/dockerize`: when the consumer project has a `.env`, it appends every `VAR=` from `.env.example` that `.env` doesn't define, with the comment lines directly above it (a blank line resets them, so the file's header comment is skipped). It never changes existing values and never creates `.env`. Keep each setting as a comment block + `VAR=` separated by blank lines.
- **`deploy.template.yml`** is a sample Deployer config (Laravel recipe + `frankenphp:release` before `deploy:symlink` and `frankenphp:up` after). It is not in the `FILES` list: `bash/dockerize` downloads it straight to `deploy.yml` only when the project has none (never overwrites it, and never leaves a `deploy.template.yml` in the consumer project). This repo is public: keep real hosts, IPs, users and repositories out of it (use `<placeholders>`).

## Gotchas

- The script's user-facing messages use emoji prefixes (👻 errors, 💡 verbose info, 🔒/🔓 TLS mode, 👀 config, 🌐 next steps). Some comments are in Spanish.
